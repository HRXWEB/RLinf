RL with F1 Dual-Arm Peg Insertion
=================================

Use this recipe to run the simplified F1 dual-arm peg-insertion chain from one
Hydra YAML. You validate the Controller, start a two-node Ray cluster, prove the
Fake backend path, then run one supervised real-motion step before a bounded
10-step async SAC/RLPD experiment.

Overview
--------

Follow the same user path for Fake and ROS 2: configure one YAML, diagnose the
robot, launch Ray, run a short smoke, then inspect replay and logs.

Architecture and Node Roles
---------------------------

Run the entry script only on the GPU head node. The head hosts Actor and
Rollout. The Thor worker hosts the Env Worker and Controller backend.

.. list-table::
   :header-rows: 1
   :widths: 20 26 54

   * - Node
     - Rank
     - Role
   * - GPU server
     - ``RLINF_NODE_RANK=0``
     - Ray head, ActorGroup, RolloutGroup, replay sampling, optimizer, and logs.
   * - F1 Thor
     - ``RLINF_NODE_RANK=1``
     - Ray worker, EnvGroup, Controller ``backend: ros2``, sensor reads, and bounded commands.

.. warning::

   Set ``RLINF_NODE_RANK`` before ``ray start`` on each node. Ray captures the
   environment at startup, so changing the variable later does not repair node
   placement.

Installation
------------

Prepare the GPU Python environment and the Thor image with the runtime guide:
:doc:`F1 Two-Node Runtime </rst_source/guides/f1_runtime>`.

On the GPU server, install a Python ``3.12.3`` environment:

.. code-block:: bash

   bash requirements/install.sh embodied --env dummy --python 3.12.3 --venv .venv-f1 --install-rlinf
   source .venv-f1/bin/activate
   python -c "import platform, ray; assert platform.python_version() == '3.12.3'; assert ray.__version__ == '2.57.0'"

On Thor, use the F1 container image built from ``docker/f1/Dockerfile``. It
contains ROS 2 Jazzy, Controller ``0.2.0``, Ray ``2.57.0``, and the RLinf source.

What this does: the GPU env keeps CUDA/training dependencies on the server; the
Thor image keeps ROS 2 and robot communication on the robot computer.

Edit One YAML
-------------

Start from ``examples/embodiment/config/realworld_f1_peg_rlpd_cnn_async.yaml``.
Keep the runtime contract inline:

.. code-block:: yaml

   runner:
     logger:
       log_path: ./logs/f1-peg-rlpd
   actor:
     model:
       model_path: /path/to/RLinf-ResNet10-pretrained
   rollout:
     model:
       model_path: ${actor.model.model_path}
   env:
     train:
       max_episode_steps: 10
       override_cfg:
         controller:
           backend: ros2
         action_scale:
           tcp_position_m: 0.005
           tcp_orientation_deg: 1.0
           gripper_percent_closed: 10.0
         motion_envelope:
           gripper_percent_closed: [0.0, 100.0]
         max_num_steps: 10

What this does: ``controller.backend`` selects ``fake`` or ``ros2``;
``action_scale`` maps policy actions to meters, degrees, and gripper percent;
``motion_envelope`` is the Controller safety boundary. Override ordinary keys
with Hydra CLI syntax, for example ``actor.model.model_path=/models/f1-cnn`` or
``runner.logger.log_path=/runs/f1-smoke``.

Run Controller Diagnostics
--------------------------

Run diagnostics on Thor before any RLinf entry script starts:

.. code-block:: bash

   controller_json="$(mktemp /tmp/f1-controller.XXXXXX.json)"
   EMBODIED_PATH="$PWD/examples/embodiment" \
   python - "$controller_json" <<'PY'
   import json
   import sys
   from pathlib import Path

   from hydra import compose, initialize_config_dir
   from omegaconf import OmegaConf

   output = Path(sys.argv[1])
   with initialize_config_dir(
       config_dir=str(
           Path.cwd() / "examples" / "embodiment" / "config"
       ),
       version_base=None,
   ):
       cfg = compose(config_name="realworld_f1_peg_rlpd_cnn_async")
   override_cfg = OmegaConf.to_container(
       cfg.env.train.override_cfg,
       resolve=True,
   )
   controller = dict(override_cfg["controller"])
   controller["motion_envelope"] = override_cfg["motion_envelope"]
   output.write_text(json.dumps(controller, indent=2, sort_keys=True) + "\n")
   PY
   f1-controller doctor --config "$controller_json"
   f1-controller read-state --config "$controller_json"

What this does: you keep editing one Hydra YAML, then extract the
Controller-owned mapping plus sibling ``motion_envelope`` into a temporary
controller JSON for the CLI. ``f1-controller doctor`` checks ROS 2 discovery,
topic types, freshness, skew, and read-only connectivity. ``f1-controller
read-state`` prints the normalized current robot state that reset will use as
the session origin.

Start Ray on Both Nodes
-----------------------

Start Ray after sourcing the setup script on both nodes.

On the GPU server:

.. code-block:: bash

   export F1_RUNTIME_ROLE=gpu
   export F1_VENV_PATH="$PWD/.venv-f1"
   export RLINF_COMM_NET_DEVICES=<GPU_INTERFACE>
   export RLINF_NODE_RANK=0
   source ray_utils/realworld/f1/setup_before_ray.sh
   ray start --head --port=6379 --node-ip-address=<GPU_SERVER_IP>

On Thor:

.. code-block:: bash

   docker run --rm --network host --name f1-ray-worker f1-rlinf-env:runtime-simplified bash -lc '
     export F1_RUNTIME_ROLE=thor
     export F1_VENV_PATH=/opt/rlinf-venv
     export RLINF_COMM_NET_DEVICES=<THOR_INTERFACE>
     export RLINF_NODE_RANK=1
     source ray_utils/realworld/f1/setup_before_ray.sh
     ray start --address=<GPU_SERVER_IP>:6379 --node-ip-address=<THOR_IP> --block
   '

Run Fake Architecture Smoke
---------------------------

Launch the Fake backend smoke on the GPU server:

.. code-block:: bash

   EMBODIED_PATH="$PWD/examples/embodiment" \
   python examples/embodiment/train_async.py \
     --config-name realworld_dummy_f1_peg_sac_cnn_async

What this does: the single-node Fake config runs the same 14D action schema,
10-step horizon, replay descriptor, one SAC update path, and weight sync without
touching ROS 2 or the robot.

Run One-Step Real Motion Smoke
------------------------------

Use this only after the operator confirmation is complete. Confirm the workcell
is clear, the robot is in the expected pose, the emergency stop is reachable,
and the operator is ready to stop motion.

.. code-block:: bash

   EMBODIED_PATH="$PWD/examples/embodiment" \
   python examples/embodiment/train_async.py \
     --config-name realworld_f1_peg_rlpd_cnn_async \
     runner.max_steps=1 \
     env.train.max_episode_steps=1 \
     env.train.override_cfg.max_num_steps=1 \
     algorithm.replay_buffer.auto_save=false

What this does: reset reads the current measured state as the session origin,
one policy action passes through ``action_scale`` and Controller
``motion_envelope``, and the Controller stops motion on rejection or command
failure. The entry script still runs only on the GPU head node.

Run 10-Step Async Training Chain
--------------------------------

Launch the bounded ROS 2 async chain from the GPU head:

.. code-block:: bash

   EMBODIED_PATH="$PWD/examples/embodiment" \
   python examples/embodiment/train_async.py \
     --config-name realworld_f1_peg_rlpd_cnn_async

What this does: ActorGroup and RolloutGroup run on the ``gpu`` node group;
EnvGroup runs on the ``f1`` node group through ``/opt/rlinf-venv/bin/python``.
The episode horizon is 10 steps. Step 10 returns ``truncated=true``.

Visualization and Results
-------------------------

Inspect logs and replay before repeating a real run.

.. list-table::
   :header-rows: 1
   :widths: 34 66

   * - Output
     - Check
   * - ``./logs/f1-peg-rlpd``
     - Open TensorBoard and inspect SAC losses, replay counts, and timing. See :doc:`Training Metrics </rst_source/reference/metrics>`.
   * - ``./logs/f1-peg-rlpd/online-replay``
     - Validate saved replay with ``python toolkits/f1/validate_f1_dataset.py --dataset ./logs/f1-peg-rlpd/online-replay``.
   * - Replay audit fields
     - Confirm normalized action, physical delta, absolute target, timestamps, reward, and ``truncated`` match the run.
   * - Safety stop
     - Stop the runner with ``Ctrl+C``, then run ``ray stop`` on both nodes. If a Controller fault appears, stop robot motion first and discard the incomplete trajectory.

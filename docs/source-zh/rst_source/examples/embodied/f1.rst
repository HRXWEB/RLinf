F1 双臂插销强化学习
===================

使用这份配方从一份 Hydra YAML 启动简化后的 F1 双臂插销链路。你会验证
Controller，启动双节点 Ray，先用 Fake backend 验证链路，再在人工确认后执行
一步真机动作，最后运行受限的 10 步 async SAC/RLPD 实验。

Overview
--------

Fake 和 ROS 2 使用同一条路径：配置一个 YAML，诊断机器人，启动 Ray，运行
smoke，再检查 replay 和日志。

Architecture and Node Roles
---------------------------

只在 GPU head 节点启动 entry script。head 承载 Actor 和 Rollout；Thor worker
承载 Env Worker 和 Controller backend。

.. list-table::
   :header-rows: 1
   :widths: 20 26 54

   * - 节点
     - Rank
     - 角色
   * - GPU server
     - ``RLINF_NODE_RANK=0``
     - Ray head、ActorGroup、RolloutGroup、replay sampling、optimizer 和 logs。
   * - F1 Thor
     - ``RLINF_NODE_RANK=1``
     - Ray worker、EnvGroup、Controller ``backend: ros2``、sensor reads 和 bounded commands。

.. warning::

   在每个节点执行 ``ray start`` 之前设置 ``RLINF_NODE_RANK``。Ray 在启动时捕获
   环境变量，之后再修改不会修复 placement。

Installation
------------

按照运行时页面准备 GPU Python 环境和 Thor 镜像：
:doc:`F1 双节点运行时 </rst_source/guides/f1_runtime>`。

在 GPU server 上安装 Python ``3.12.3`` 环境：

.. code-block:: bash

   bash requirements/install.sh embodied --env dummy --python 3.12.3 --venv .venv-f1 --install-rlinf
   source .venv-f1/bin/activate
   python -c "import platform, ray; assert platform.python_version() == '3.12.3'; assert ray.__version__ == '2.57.0'"

在 Thor 上使用由 ``docker/f1/Dockerfile`` 构建的 F1 container image。它包含
ROS 2 Jazzy、Controller ``0.2.0``、Ray ``2.57.0`` 和 RLinf source。

What this does: GPU env 保留 CUDA/training dependencies；Thor image 保留 ROS 2
和 robot communication。

Edit One YAML
-------------

从 ``examples/embodiment/config/realworld_f1_peg_rlpd_cnn_async.yaml`` 开始。
保持 runtime contract 内联：

.. code-block:: yaml

   runner:
     logger:
       log_path: ./logs/f1-peg-rlpd
   actor:
     model:
       model_path: /path/to/RLinf-ResNet10-pretrained
   rollout:
     model:
       model_path: ${actor.model.model_path}
   env:
     train:
       max_episode_steps: 10
       override_cfg:
         controller:
           backend: ros2
         action_scale:
           tcp_position_m: 0.005
           tcp_orientation_deg: 1.0
           gripper_percent_closed: 10.0
         motion_envelope:
           gripper_percent_closed: [0.0, 100.0]
         max_num_steps: 10

What this does: ``controller.backend`` 选择 ``fake`` 或 ``ros2``；
``action_scale`` 把策略动作映射到米、角度和夹爪百分比；
``motion_envelope`` 是 Controller safety boundary。使用普通 Hydra CLI 覆盖键，
例如 ``actor.model.model_path=/models/f1-cnn`` 或
``runner.logger.log_path=/runs/f1-smoke``。

Run Controller Diagnostics
--------------------------

在 Thor 上运行诊断，然后再启动任何 RLinf entry script：

.. code-block:: bash

   controller_json="$(mktemp /tmp/f1-controller.XXXXXX.json)"
   EMBODIED_PATH="$PWD/examples/embodiment" \
   python - "$controller_json" <<'PY'
   import json
   import sys
   from pathlib import Path

   from hydra import compose, initialize_config_dir
   from omegaconf import OmegaConf

   output = Path(sys.argv[1])
   with initialize_config_dir(
       config_dir=str(
           Path.cwd() / "examples" / "embodiment" / "config"
       ),
       version_base=None,
   ):
       cfg = compose(config_name="realworld_f1_peg_rlpd_cnn_async")
   override_cfg = OmegaConf.to_container(
       cfg.env.train.override_cfg,
       resolve=True,
   )
   controller = dict(override_cfg["controller"])
   controller["motion_envelope"] = override_cfg["motion_envelope"]
   output.write_text(json.dumps(controller, indent=2, sort_keys=True) + "\n")
   PY
   f1-controller doctor --config "$controller_json"
   f1-controller read-state --config "$controller_json"

What this does: 你仍然只编辑一个 Hydra YAML，然后把 Controller-owned mapping
和 sibling ``motion_envelope`` 提取成临时 controller JSON 给 CLI 使用。
``f1-controller doctor`` 检查 ROS 2 discovery、topic types、freshness、skew 和
read-only connectivity。``f1-controller read-state`` 打印 reset 将作为 session
origin 使用的 normalized current robot state。

Start Ray on Both Nodes
-----------------------

在两个节点 source setup script 后再启动 Ray。

GPU server：

.. code-block:: bash

   export F1_RUNTIME_ROLE=gpu
   export F1_VENV_PATH="$PWD/.venv-f1"
   export RLINF_COMM_NET_DEVICES=<GPU_INTERFACE>
   export RLINF_NODE_RANK=0
   source ray_utils/realworld/f1/setup_before_ray.sh
   ray start --head --port=6379 --node-ip-address=<GPU_SERVER_IP>

Thor：

.. code-block:: bash

   docker run --rm --network host --name f1-ray-worker f1-rlinf-env:runtime-simplified bash -lc '
     export F1_RUNTIME_ROLE=thor
     export F1_VENV_PATH=/opt/rlinf-venv
     export RLINF_COMM_NET_DEVICES=<THOR_INTERFACE>
     export RLINF_NODE_RANK=1
     source ray_utils/realworld/f1/setup_before_ray.sh
     ray start --address=<GPU_SERVER_IP>:6379 --node-ip-address=<THOR_IP> --block
   '

Run Fake Architecture Smoke
---------------------------

在 GPU server 上启动 Fake backend smoke：

.. code-block:: bash

   EMBODIED_PATH="$PWD/examples/embodiment" \
   python examples/embodiment/train_async.py \
     --config-name realworld_dummy_f1_peg_sac_cnn_async

What this does: 单节点 Fake config 运行同样的 14D action schema、10-step
horizon、replay descriptor、一次 SAC update path 和 weight sync，不接触 ROS 2
或机器人。

Run One-Step Real Motion Smoke
------------------------------

只在 operator confirmation 完成后使用这一步。确认工作区清空，机器人处于预期
姿态，急停可触达，并且操作者已经准备好停止 motion。

.. code-block:: bash

   EMBODIED_PATH="$PWD/examples/embodiment" \
   python examples/embodiment/train_async.py \
     --config-name realworld_f1_peg_rlpd_cnn_async \
     runner.max_steps=1 \
     env.train.max_episode_steps=1 \
     env.train.override_cfg.max_num_steps=1 \
     algorithm.replay_buffer.auto_save=false

What this does: reset 读取当前 measured state 作为 session origin；一个 policy
action 经过 ``action_scale`` 和 Controller ``motion_envelope``；Controller 在
rejection 或 command failure 时停止 motion。entry script 仍然只在 GPU head 节点运行。

Run 10-Step Async Training Chain
--------------------------------

从 GPU head 启动受限 ROS 2 async 链路：

.. code-block:: bash

   EMBODIED_PATH="$PWD/examples/embodiment" \
   python examples/embodiment/train_async.py \
     --config-name realworld_f1_peg_rlpd_cnn_async

What this does: ActorGroup 和 RolloutGroup 在 ``gpu`` node group；EnvGroup 通过
``/opt/rlinf-venv/bin/python`` 在 ``f1`` node group。episode horizon 是 10 步；
第 10 步返回 ``truncated=true``。

Visualization and Results
-------------------------

再次真机运行前检查 logs 和 replay。

.. list-table::
   :header-rows: 1
   :widths: 34 66

   * - 输出
     - 检查
   * - ``./logs/f1-peg-rlpd``
     - 打开 TensorBoard，检查 SAC losses、replay counts 和 timing。参考 :doc:`Training Metrics </rst_source/reference/metrics>`。
   * - ``./logs/f1-peg-rlpd/online-replay``
     - 使用 ``python toolkits/f1/validate_f1_dataset.py --dataset ./logs/f1-peg-rlpd/online-replay`` 验证保存的 replay。
   * - Replay audit fields
     - 确认 normalized action、physical delta、absolute target、timestamps、reward 和 ``truncated`` 与本次运行一致。
   * - Safety stop
     - 用 ``Ctrl+C`` 停止 runner，然后在两个节点运行 ``ray stop``。如果出现 Controller fault，先停止 robot motion，并丢弃未完成 trajectory。

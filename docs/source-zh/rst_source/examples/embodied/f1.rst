F1 双臂插销强化学习
===================

使用 online SAC 或 RLPD 为 F1 双臂插销任务训练 CNN 策略。GPU 节点运行
Actor 和 Rollout Worker，机器人侧节点运行 Env Worker 和 ROS 2 Controller
backend。

概览
----

在一份 Hydra YAML 中配置机器人和训练参数，诊断 Controller，启动双节点 Ray
集群，然后从 GPU head 节点启动训练。

右臂固定目标简化任务
~~~~~~~~~~~~~~~~~~~~

对于“右夹爪已夹好插入物、孔位固定”的简化任务，使用
``realworld_f1_right_arm_peg_rlpd_cnn_async``。它对应的
``F1RightArmPegInsertionEnv-v0`` policy 接口只包含一张 ``head_color`` 图像、
6D 右臂 TCP pose 和 6D normalized 右臂 TCP delta。wrapper 对左臂和两个夹爪
发送零增量，因此它们保持各自的测量状态。

任务只使用一项标定：``target_tcp_pose_m_deg``。它是从
``/state/right_arm/tcp_pos`` 读取的最终 ``[x, y, z, rx, ry, rz]`` 位姿，位置单位
为米、姿态单位为度，reference 是 Controller native
``right_arm_tcp_pose``。环境不要求 pre-insert waypoint 或 approach axis，因此
demonstration 可以沿不同路径接近目标。

dense reward 是加权且归一化的线性 position/orientation target 势函数之差，再减去
``step_penalty``。与指数势函数不同，即使 TCP 初始位置离目标较远，它也仍然提供
学习信号；保持静止则不能持续获得正 reward。position 和 orientation error 连续
``success_hold_steps`` 次满足阈值后，只发放一次 bonus；
由于 ``ignore_terminations`` 为 false，episode 随即结束。horizon 为 50 个 policy
step，在 10 Hz 下即 5 秒。任务配置首先在同一个 CNN actor 上执行
``algorithm.bc_warmup_updates`` 次 demo-only Gaussian BC 更新，并保存
``global_step_0``，随后才启动异步 RLPD。``algorithm.update_epoch`` 控制每个在线
step 对应的 SAC replay 更新次数。``algorithm.bc_log_interval`` 控制 warmup 阶段向
TensorBoard 写入 ``bc/loss`` 和 ``bc/action_mae`` 曲线点的频率。共享 reward 定义变化后必须重新生成 demo buffer，
以保证离线和在线 transition 使用相同 reward。

右臂 XYZ Reach 课程阶段
~~~~~~~~~~~~~~~~~~~~~~~

使用 ``realworld_f1_right_arm_reach_sac_cnn_async`` 训练无需 demonstration 的
第一阶段课程任务。``F1RightArmFixedReachEnv-v0`` 观测完整的右腕 RGB 图像；环境将
图像从 ``848×480`` 直接缩放为 ``224×128``，不做裁剪，同时观测右臂 TCP 的 XYZ
实测位置。policy 输出 3D normalized XYZ delta；环境将 TCP 姿态固定为
``[90, 0, 90]`` 度，并保持其他 actuator 不变。

仓库中的配置使用 5 mm action scale，并按照 ``base_link`` 坐标约定，将每次候选 TCP
位置裁剪到相对目标定义的标定包围盒内。5 mm command margin 会把命令目标限制在
物理包围盒内侧，为跟踪误差预留空间。该配置只使用 online replay 训练 SAC：
``algorithm.demo_buffer`` 为 null，``algorithm.bc_warmup_updates`` 为零。上真机前，
第一阶段课程使用 XY 10 mm、Z 5 mm 的成功容差，并要求连续保持 3 步；后续精确阶段
再收紧容差。首次成功步骤的 reward 精确为 1.0，并替代该步的 dense progress 和
step penalty，使 ``env/success_once`` 遵循 RealWorld 的 reward 约定。
请根据当前机器人设置复核 target pose、reset joint pose、
``vendor_to_base_rotation`` 和 workspace offset。

架构与节点角色
--------------

只在 GPU head 节点启动 entry script。head 训练 Actor 并运行 Rollout 推理；
机器人侧 worker 承载 Env Worker 和 Controller backend。当前 container 已在
NVIDIA Thor 上验证，runtime 边界是运行 ROS 2 Jazzy 的 ARM64 Linux 节点。

.. list-table::
   :header-rows: 1
   :widths: 20 26 54

   * - 节点
     - Rank
     - 角色
   * - GPU server
     - ``RLINF_NODE_RANK=0``
     - Ray head、ActorGroup、RolloutGroup、replay sampling、optimizer 和 logs。
   * - F1 机器人节点
     - ``RLINF_NODE_RANK=1``
     - Ray worker、EnvGroup、Controller ``backend: ros2``、sensor reads 和 bounded commands。

.. warning::

   在每个节点执行 ``ray start`` 之前设置 ``RLINF_NODE_RANK``。Ray 在启动时捕获
   环境变量，之后再修改不会修复 placement。

安装
----

按照 :doc:`F1 双节点运行时 </rst_source/guides/f1_runtime>` 准备 GPU Python
环境和机器人侧镜像。

在 GPU server 上先安装 embodied dependencies，再把共享 F1 runtime constraints
和 Controller package 安装到同一个 Python ``3.12.3`` 环境：

.. code-block:: bash

   bash requirements/install.sh embodied \
     --env dummy \
     --python 3.12.3 \
     --venv .venv-f1 \
     --install-rlinf
   F1_ROBOT_CONTROLLER_PACKAGE=<wheel-path-package-url-or-pinned-git-url> \
     bash requirements/install.sh f1-realworld \
       --python 3.12.3 \
       --venv .venv-f1
   source .venv-f1/bin/activate
   python -c "import f1_robot_controller, platform, ray; assert platform.python_version() == '3.12.3'; assert ray.__version__ == '2.57.0'; assert callable(f1_robot_controller.create_controller)"

机器人计算机使用由 ``docker/f1/Dockerfile`` 构建的 F1 container image。它包含
ROS 2 Jazzy、用户提供的 Controller package、Ray ``2.57.0`` 和 RLinf source。

What this does: GPU env 保留 CUDA/training dependencies；机器人侧 image 保留
ROS 2 和 robot communication。

下载模型
--------

在 GPU server 上下载预训练 ResNet CNN backbone：

.. code-block:: bash

   hf download RLinf/RLinf-ResNet10-pretrained \
     --local-dir RLinf-ResNet10-pretrained

将 ``actor.model.model_path`` 设置为下载目录。Rollout 通过
``${actor.model.model_path}`` 使用同一路径。

配置训练
--------

从 ``examples/embodiment/config/realworld_f1_peg_rlpd_cnn_async.yaml`` 开始。
在 YAML 中设置 ``actor.model.model_path``、``runner.logger.log_path``、Controller
topic、``action_scale``、``motion_envelope`` 和采集长度。以下三个字段分别控制
episode、rollout epoch 和任务环境的步数：

.. code-block:: yaml

   env:
     train:
       max_episode_steps: 10
       max_steps_per_rollout_epoch: 10
       override_cfg:
         max_num_steps: 10

根据需要将它们设为正整数。``action_scale`` 把 normalized policy action 映射为
物理增量；``motion_envelope`` 限制 Controller command。

运行 Controller 诊断
---------------------

在机器人侧节点运行诊断，然后再启动 RLinf entry script：

.. code-block:: bash

   controller_json="$(mktemp /tmp/f1-controller.XXXXXX.json)"
   EMBODIED_PATH="$PWD/examples/embodiment" \
   python - "$controller_json" <<'PY'
   import json
   import sys
   from pathlib import Path

   from hydra import compose, initialize_config_dir
   from omegaconf import OmegaConf

   output = Path(sys.argv[1])
   with initialize_config_dir(
       config_dir=str(
           Path.cwd() / "examples" / "embodiment" / "config"
       ),
       version_base=None,
   ):
       cfg = compose(config_name="realworld_f1_peg_rlpd_cnn_async")
   override_cfg = OmegaConf.to_container(
       cfg.env.train.override_cfg,
       resolve=True,
   )
   controller = dict(override_cfg["controller"])
   controller["motion_envelope"] = override_cfg["motion_envelope"]
   output.write_text(json.dumps(controller, indent=2, sort_keys=True) + "\n")
   PY
   f1-controller doctor --config "$controller_json"
   f1-controller read-state --config "$controller_json"

What this does: 从 Hydra YAML 提取 Controller-owned mapping 和 sibling
``motion_envelope``，生成临时 controller JSON。``doctor`` 检查 ROS 2 discovery、
topic types、freshness 和 skew；``read-state`` 读取 normalized current state。

启动双节点 Ray
--------------

GPU server：

.. code-block:: bash

   export F1_RUNTIME_ROLE=gpu
   export F1_VENV_PATH="$PWD/.venv-f1"
   export RLINF_COMM_NET_DEVICES=<GPU_INTERFACE>
   export RLINF_NODE_RANK=0
   source ray_utils/realworld/f1/setup_before_ray.sh
   ray start --head --port=6379 --node-ip-address=<GPU_SERVER_IP>

机器人侧 ARM64 节点（已在 NVIDIA Thor 上验证）：

.. code-block:: bash

   docker run --rm --network host --name f1-ray-worker f1-rlinf-env:runtime-simplified bash -lc '
     export F1_RUNTIME_ROLE=thor
     export F1_VENV_PATH=/opt/rlinf-venv
     export RLINF_COMM_NET_DEVICES=<ROBOT_INTERFACE>
     export RLINF_NODE_RANK=1
     source ray_utils/realworld/f1/setup_before_ray.sh
     ray start --address=<GPU_SERVER_IP>:6379 --node-ip-address=<ROBOT_IP> --block
   '

准备 RLPD Demonstration
-----------------------

F1 RLPD 配置要求非空 demonstration buffer。将
``algorithm.demo_buffer.load_path`` 设置为同一任务采集的 RLinf replay buffer，
并确保 observation 和 14 维 action 的 shape 与当前配置一致。

如果只训练 online SAC，请删除 demo-buffer mapping：

.. code-block:: bash

   '~algorithm.demo_buffer'

运行训练
--------

确认机器人工作区已清空、急停可触达，并由受过训练的操作者现场看护。然后从 GPU
head 启动 RLPD 训练：

.. code-block:: bash

   EMBODIED_PATH="$PWD/examples/embodiment" \
   python examples/embodiment/train_async.py \
     --config-name realworld_f1_peg_rlpd_cnn_async \
     actor.model.model_path=/path/to/RLinf-ResNet10-pretrained \
     algorithm.demo_buffer.load_path=/path/to/f1-peg-demo-buffer

纯 online SAC 在命令末尾追加：

.. code-block:: bash

   '~algorithm.demo_buffer'

What this does: ActorGroup 和 RolloutGroup 在 ``gpu`` node group；EnvGroup 通过
``/opt/rlinf-venv/bin/python`` 在 ``f1`` node group。
